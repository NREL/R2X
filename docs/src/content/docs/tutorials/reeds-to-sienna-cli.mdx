---
title: Translate ReEDS with the CLI
description: Configure, preview, execute, and inspect a ReEDS-to-Sienna pipeline.
---

Turn a completed ReEDS run into a Sienna model using three installed plugins.
Start with the [first CLI pipeline](/R2X/tutorials/getting-started/) if you have not used pipeline files before.

## Required inputs

You need a completed ReEDS run directory containing its `inputs_case/` and `outputs/` data.
Use solve and weather years present in that run.
The parser loads the datasets named by its installed file mapping.
A ReEDS model and run data are external to this repository; this page's list, resolved configuration, and dry-run commands were verified, but a complete ReEDS translation was not executed without those inputs.

## Install and inspect the plugins

From your workspace, install the translation package and its dependencies:

```bash
r2x install r2x-reeds-to-sienna
```

Inspect the registered entry points and parser options:

```bash
r2x list && r2x run reeds-parser --help && r2x run reeds-to-sienna --help
```

The pipeline needs `reeds-parser`, `reeds-to-sienna`, and `sienna-exporter`.
The parser requires `solve_year` and `weather_year`.
The translation uses [ReEDSToSiennaConfig](/R2X/reference/python-api/#reedstosiennaconfig).

## Configure the translation

Save this as `reeds-pipeline.yaml`.
Replace the absolute run path, case name, and years with your completed model run:

```yaml
variables:
  run_dir: /path/to/ReEDS/runs/my-case
  solve_year: 2035
  weather_year: 2012
pipelines:
  reeds-to-sienna:
    - reeds-parser
    - reeds-to-sienna
    - sienna-exporter
config:
  reeds-parser:
    path: ${run_dir}
    case_name: my-case
    solve_year: ${solve_year}
    weather_year: ${weather_year}
  reeds-to-sienna: {}
  sienna-exporter:
    output_path: outputs/my-case.json
output_folder: outputs
```

`path` supplies the parser's data store.
The empty translation configuration uses the package defaults.
The parser uses the solve year as its model year; the exporter writes to the configured output path.
Keep the JSON export and its companion time-series file together.

## Check before running

From the directory containing the YAML file:

```bash
r2x run reeds-pipeline.yaml reeds-to-sienna --print
```

Check that the resolved path and both years match your run.
Then preview the execution order:

```bash
r2x run reeds-pipeline.yaml reeds-to-sienna --dry-run
```

Expect `reeds-parser → reeds-to-sienna → sienna-exporter`.
A successful dry run does not validate ReEDS datasets or target model values.

## Execute and inspect

Create the output directory and execute the pipeline:

```bash
mkdir -p outputs && r2x run reeds-pipeline.yaml reeds-to-sienna --zip -o outputs/my-case-system.zip
```

Success creates the Sienna JSON and companion time-series file under `outputs/`, plus `my-case-system.zip` for inspection.
Open the portable result:

```bash
r2x read outputs/my-case-system.zip --zip
```

Inspect the system summary and component counts against the source run.
Use `sys.info()` to print the summary again in the interactive session.

## Troubleshooting and next steps

| Symptom | Action |
| --- | --- |
| Missing required dataset | Check the parser's file mapping against the actual run directory, then verify the solve and weather years. |
| Missing plugin | Inspect `r2x list`. Install the package into the environment reported by `r2x python show`. |
| Execution fails after dry-run succeeds | Read the log path printed during execution. Retry with `-v` to identify the failing plugin and dataset. |
| Unexpected generator, reserve, or transmission mapping | Compare the [property reference](/R2X/reference/reeds-to-sienna-properties/) and its pinned source rules with the source components. |

For Python integration and detailed mapping behavior, see [ReEDS to Sienna](/R2X/how-to/reeds-to-sienna/).
